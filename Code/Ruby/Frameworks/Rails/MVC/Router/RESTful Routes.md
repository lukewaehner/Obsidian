# RESTful Routes

The seven standard CRUD routes generated by `resources`.

## Overview

Rails embraces REST (Representational State Transfer) by providing a single method—`resources`—that generates all seven routes needed to create, read, update, and delete a resource. This convention reduces boilerplate and ensures consistent URL patterns across your application.

## The Seven Routes

```ruby
# config/routes.rb
resources :posts
```

This single line generates:

| Helper | HTTP Verb | Path | Controller#Action | Purpose |
|--------|-----------|------|-------------------|---------|
| `posts_path` | GET | `/posts` | `posts#index` | List all posts |
| `post_path(id)` | GET | `/posts/:id` | `posts#show` | Show one post |
| `new_post_path` | GET | `/posts/new` | `posts#new` | Form for new post |
| `posts_path` | POST | `/posts` | `posts#create` | Create the post |
| `edit_post_path(id)` | GET | `/posts/:id/edit` | `posts#edit` | Form to edit post |
| `post_path(id)` | PATCH/PUT | `/posts/:id` | `posts#update` | Update the post |
| `post_path(id)` | DELETE | `/posts/:id` | `posts#destroy` | Delete the post |

## The Long Way

Without `resources`, you'd write each route manually:

```ruby
# config/routes.rb
get    "/posts",          to: "posts#index"
get    "/posts/new",      to: "posts#new"
get    "/posts/:id",      to: "posts#show"
post   "/posts",          to: "posts#create"
get    "/posts/:id/edit", to: "posts#edit"
patch  "/posts/:id",      to: "posts#update"
put    "/posts/:id",      to: "posts#update"
delete "/posts/:id",      to: "posts#destroy"
```

## The Controller

A RESTful controller implements all seven actions:

```ruby
# app/controllers/posts_controller.rb
class PostsController < ApplicationController
  before_action :set_post, only: [:show, :edit, :update, :destroy]
  
  # GET /posts
  def index
    @posts = Post.all
  end
  
  # GET /posts/:id
  def show
  end
  
  # GET /posts/new
  def new
    @post = Post.new
  end
  
  # POST /posts
  def create
    @post = Post.new(post_params)
    if @post.save
      redirect_to @post, notice: "Post created."
    else
      render :new, status: :unprocessable_entity
    end
  end
  
  # GET /posts/:id/edit
  def edit
  end
  
  # PATCH/PUT /posts/:id
  def update
    if @post.update(post_params)
      redirect_to @post, notice: "Post updated."
    else
      render :edit, status: :unprocessable_entity
    end
  end
  
  # DELETE /posts/:id
  def destroy
    @post.destroy
    redirect_to posts_path, notice: "Post deleted."
  end
  
  private
  
  def set_post
    @post = Post.find(params[:id])
  end
  
  def post_params
    params.require(:post).permit(:title, :content)
  end
end
```

## Limiting Routes

### Only Specific Actions

```ruby
resources :posts, only: [:index, :show]
# Generates only:
# GET /posts        -> posts#index
# GET /posts/:id    -> posts#show
```

### Excluding Actions

```ruby
resources :users, except: [:destroy]
# Generates all 7 except DELETE /users/:id
```

### Common Patterns

```ruby
# API: No new/edit (those are form pages)
resources :posts, only: [:index, :show, :create, :update, :destroy]

# Read-only resource
resources :articles, only: [:index, :show]

# No deletion allowed
resources :orders, except: [:destroy]
```

## Nested Resources

Resources that belong to other resources:

```ruby
resources :posts do
  resources :comments
end
```

Generates routes like:
- `GET /posts/:post_id/comments` → `comments#index`
- `POST /posts/:post_id/comments` → `comments#create`
- `GET /posts/:post_id/comments/:id` → `comments#show`

```ruby
# In CommentsController
def create
  @post = Post.find(params[:post_id])
  @comment = @post.comments.build(comment_params)
  # ...
end

# Path helpers
post_comments_path(@post)            # => "/posts/42/comments"
post_comment_path(@post, @comment)   # => "/posts/42/comments/7"
```

### Shallow Nesting

Avoid deeply nested URLs:

```ruby
resources :posts do
  resources :comments, shallow: true
end
```

- `GET /posts/:post_id/comments` — Needs parent context
- `GET /comments/:id` — Doesn't need parent
- `PATCH /comments/:id` — Doesn't need parent

## Singular Resources

For resources where only one exists (current user's profile):

```ruby
resource :profile  # Note: singular, no 's'
```

| Helper | Verb | Path | Action |
|--------|------|------|--------|
| `new_profile_path` | GET | `/profile/new` | `profiles#new` |
| `profile_path` | POST | `/profile` | `profiles#create` |
| `profile_path` | GET | `/profile` | `profiles#show` |
| `edit_profile_path` | GET | `/profile/edit` | `profiles#edit` |
| `profile_path` | PATCH | `/profile` | `profiles#update` |
| `profile_path` | DELETE | `/profile` | `profiles#destroy` |

No `:id` parameter needed—there's only one.

## Tips

- Use `resources` by default—it's the Rails way
- Use `only:` to expose minimal routes for security
- Nest resources only one level deep
- Use `shallow: true` to avoid long nested URLs
- Run `bin/rails routes` to verify your routes
- Singular `resource` for things like profile, settings, cart
