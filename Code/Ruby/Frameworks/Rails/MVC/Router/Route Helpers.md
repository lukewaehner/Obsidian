# Route Helpers

Path and URL helper methods generated by Rails routes.

## Overview

Rails automatically generates helper methods for your routes, eliminating the need to hardcode URLs. These helpers ensure your links stay correct even if you change your URL structure, and they handle parameter interpolation automatically.

## Path vs URL Helpers

Every route generates two helpers:

```ruby
# _path: Relative path (for internal links)
posts_path          # => "/posts"
post_path(@post)    # => "/posts/42"

# _url: Full URL with protocol and host (for emails, external links, APIs)
posts_url           # => "https://example.com/posts"
post_url(@post)     # => "https://example.com/posts/42"
```

**When to use which:**
- `_path` — Internal links within views (most common)
- `_url` — Emails, redirects, API responses, external links

## Viewing Available Helpers

```bash
# Command line
bin/rails routes

# Example output:
#     Prefix Verb   URI Pattern              Controller#Action
#      posts GET    /posts(.:format)         posts#index
#   new_post GET    /posts/new(.:format)     posts#new
#  edit_post GET    /posts/:id/edit(.:format) posts#edit
#       post GET    /posts/:id(.:format)     posts#show
#            PATCH  /posts/:id(.:format)     posts#update
#            DELETE /posts/:id(.:format)     posts#destroy

# Expanded view
bin/rails routes --expanded

# Filter by controller
bin/rails routes -c posts

# Filter by pattern
bin/rails routes -g edit
```

**Browser:** Visit `http://localhost:3000/rails/info/routes` while the server is running.

The **Prefix** column shows the helper name (add `_path` or `_url`).

## Using Helpers

### In Views

```erb
<!-- Basic links -->
<%= link_to "All Posts", posts_path %>
<%= link_to "View Post", post_path(@post) %>
<%= link_to "Edit", edit_post_path(@post) %>
<%= link_to "New Post", new_post_path %>

<!-- With HTML options -->
<%= link_to "Delete", post_path(@post), 
    method: :delete, 
    data: { confirm: "Are you sure?" } %>

<!-- Navigation -->
<nav>
  <%= link_to "Home", root_path %>
  <%= link_to "About", about_path %>
  <%= link_to "Contact", contact_path %>
</nav>
```

### In Controllers

```ruby
class PostsController < ApplicationController
  def create
    @post = Post.new(post_params)
    if @post.save
      redirect_to post_path(@post)  # or just: redirect_to @post
    else
      render :new
    end
  end
  
  def destroy
    @post.destroy
    redirect_to posts_path, notice: "Post deleted"
  end
end
```

### In Mailers

```ruby
class UserMailer < ApplicationMailer
  def welcome_email(user)
    @user = user
    @login_url = login_url  # Must use _url in emails!
    mail(to: @user.email, subject: "Welcome!")
  end
end
```

```erb
<!-- In mailer view -->
<p>Click here to login: <%= link_to "Login", @login_url %></p>
```

## Passing Parameters

### ID Parameters

Routes with `:id` require the record (or ID):

```ruby
post_path(@post)        # => "/posts/42"
post_path(42)           # => "/posts/42"
edit_post_path(@post)   # => "/posts/42/edit"
```

### Query String Parameters

Additional parameters become query strings:

```ruby
posts_path(page: 2)
# => "/posts?page=2"

posts_path(page: 2, sort: "title", direction: "asc")
# => "/posts?page=2&sort=title&direction=asc"

post_path(@post, referral: "newsletter")
# => "/posts/42?referral=newsletter"
```

Access in controller:

```ruby
def index
  @page = params[:page]           # => "2"
  @sort = params[:sort]           # => "title"
  @referral = params[:referral]   # => "newsletter"
end
```

### Nested Resource Parameters

```ruby
# routes.rb
resources :posts do
  resources :comments
end

# Helpers require parent
post_comments_path(@post)
# => "/posts/42/comments"

post_comment_path(@post, @comment)
# => "/posts/42/comments/7"

new_post_comment_path(@post)
# => "/posts/42/comments/new"

edit_post_comment_path(@post, @comment)
# => "/posts/42/comments/7/edit"
```

### Format Parameter

Specify response format:

```ruby
posts_path(format: :json)
# => "/posts.json"

post_path(@post, format: :xml)
# => "/posts/42.xml"
```

The `(.:format)` in route definitions means format is optional.

## Polymorphic Helpers

Rails can generate paths from objects directly:

```ruby
# These are equivalent:
post_path(@post)
polymorphic_path(@post)

# Works with arrays for nested resources:
polymorphic_path([@post, @comment])
# => "/posts/42/comments/7"

# In link_to, you can pass the object directly:
link_to "View", @post
# Equivalent to: link_to "View", post_path(@post)
```

## Named Routes

Custom routes can have explicit names:

```ruby
# config/routes.rb
get "login", to: "sessions#new", as: :login
get "logout", to: "sessions#destroy", as: :logout
get "signup", to: "registrations#new", as: :signup

# Generates:
login_path    # => "/login"
logout_path   # => "/logout"
signup_path   # => "/signup"
```

## Common Patterns

### Conditional Links

```erb
<% if current_user&.admin? %>
  <%= link_to "Admin", admin_dashboard_path %>
<% end %>

<% if @post.editable_by?(current_user) %>
  <%= link_to "Edit", edit_post_path(@post) %>
<% end %>
```

### Active Link Styling

```erb
<%= link_to "Posts", posts_path, 
    class: ("active" if current_page?(posts_path)) %>
```

### Building URLs in Background Jobs

```ruby
class NotificationJob < ApplicationJob
  include Rails.application.routes.url_helpers
  
  def perform(user, post)
    url = post_url(post, host: "example.com")
    # Send notification with url
  end
end
```

## Tips

- Use `_path` for links within your app
- Use `_url` for emails, APIs, and redirects
- Run `bin/rails routes` to see all available helpers
- Pass objects directly: `redirect_to @post` instead of `redirect_to post_path(@post)`
- Query parameters are automatically URL-encoded
- The Prefix column in `rails routes` is your helper name
