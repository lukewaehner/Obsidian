The theme is how to organize the non-programming activities so a project gets built as efficiently as possible, across three questions:

- How do we organize our development activities?
- How do we build an effective team?
- How do we estimate how long a software project will take?

This is the **Process** column of the people/processes/programs grid from [[Module 01 - Orientation and User Stories|Module 01]], and it feeds straight into the team project: Process is 8% of the course grade, and the backlog and sprint artifacts from 7.3 are what [[Preliminary Project Plan (tp2)]] asks for.

## Learning Objectives

### 7.1 Software Development Processes

- [ ] Know the basic characteristics of the waterfall software process model
- [ ] Explain when the waterfall model is appropriate and when it is not
- [ ] Understand how the waterfall and agile models manage risk
- [ ] Explain how agile processes instill quality, including through test-driven development

### 7.2 Teams

- [ ] Explain key advantages of working in a team and sharing information with your team
- [ ] Describe the HRT pillars of social interaction
- [ ] Understand why small teams are effective for agile processes
- [ ] Apply root-cause analysis to construct a blameless post-mortem of a team project

### 7.3 Project Planning and Estimation

- [ ] Describe how project planning manages uncertainty by creating detailed plans only for the most immediate tasks
- [ ] Explain how project planning decomposes large projects into individual tasks that can be estimated
- [ ] Understand the key artifacts and process steps in Scrum

## Notes

### 7.1 Software Development Processes

#### Waterfall process
Requirements | Validating -> Design | Verify -> Implementation | Test -> Operations -> Retirement
- Every step has to be confirmed, verified, and QA'd
- Measurable progress with risk contained in each phase (stop mistakes from propagating)
- Estimate phase based on past projects
