# 15 · 3Sum

> [!question]- Problem
> Return all unique triplets that sum to zero. The solution set must not contain duplicates.

## Idea

Sort, fix one number, and the rest is [[Career/Prep/problems/Two Pointers/167 · Two Sum II - Input Array Is Sorted|Two Sum II]] on what remains — the sort is what makes both the sweep *and* the deduplication possible.

## Optimal

```python
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums.sort()
        res = []

        for i in range(len(nums)):
            if i > 0 and nums[i-1] == nums[i]:
                continue
            j = i + 1
            k = len(nums) - 1
            target = -nums[i]

            while k > j:
                if nums[j] + nums[k] == target:
                    res.append([nums[i], nums[j], nums[k]])
                    k -= 1
                    j += 1
                    while k > j and nums[j] == nums[j-1]:
                        j += 1
                    while k > j and nums[k] == nums[k+1]:
                        k -= 1
                elif nums[j] + nums[k] > target:
                    k -= 1
                else:
                    j += 1
        return res
```

## Why it works

Two separate things fall out of the sort, and it is worth separating them
because only the second one is hard.

**The sweep.** Once `nums[i]` is fixed, you need two numbers from the suffix
adding to `-nums[i]`. The suffix is sorted, so that is exactly Two Sum II —
converging pointers, O(n) per fixed element, O(n²) overall. That beats the
O(n³) triple loop and needs no hash set.

**The deduplication.** This is the part worth internalising: *after sorting,
equal values are adjacent*, so "have I already used this value here?" collapses
to "is it the same as the one before it?" — a comparison, not a set.

There are two distinct places that needs to happen, and missing either one
produces duplicate triplets:

```python
if i > 0 and nums[i-1] == nums[i]:      # 1. the fixed element
    continue
```
Guarding on `i > 0` keeps the first occurrence and skips only repeats. Without
it, `[-2,-2,0,2]` yields the same triplet twice from two different `i`.

```python
while k > j and nums[j] == nums[j-1]:   # 2. the pair, after a hit
    j += 1
while k > j and nums[k] == nums[k+1]:
    k -= 1
```
These run *after* `j += 1` and `k -= 1`, so they compare against the value just
consumed. Without them, `[-2,0,0,2,2]` records `[-2,0,2]` once for each
equal pair the pointers land on.

## Mistakes I made

The decomposition — sort, fix one, two-pointer the rest — came without help.
**The duplicate skipping is where I was genuinely stumped**, and it is worth
being precise about why, because the difficulty is conceptual rather than
fiddly.

The trap is thinking of dedup as a post-processing step: collect everything,
then filter. That works but costs a set of tuples and O(n) extra space, and it
throws away the structure the sort already gave you. The insight is that
sorting has *already* grouped the duplicates — so they can be skipped in place,
at the moment they would be generated, for free.

Generalises: **when the input is sorted, "distinct" is a comparison with the
neighbour, not a set membership test.**
